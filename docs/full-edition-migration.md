# 公开版到完整运行版的迁移约定

## 1. 开发主线

现阶段以 `storycanvas-ai-staging` 作为唯一开发主线。所有稳定、通用、不包含隐私的系统能力
均先在公开版实现，依次完成本地测试、静态检查、变更日志和 Git 提交，再推送 GitHub。

早期完整运行版 `windows-image-gateway` 暂时冻结，不在两个目录中重复开发相同功能。公开版达到
毕业设计所需体量并完成后端验收后，再将完整运行版的私有能力以适配器和本地覆盖层方式接回。

## 2. 必须保持稳定的迁移边界

### 2.1 HTTP 接口

- 保持 OpenAI-compatible `/v1/chat/completions` 与 `/v1/models`。
- 通用的存档、记忆、任务、备份和导出接口继续放在 `/v1/story/*`。
- 完整版的模型或角色能力不得改变公共接口的基本响应结构。

### 2.2 数据库

- SQLite 表结构只使用向前迁移，不直接删除已有字段和数据。
- 每次结构升级提高 `PRAGMA user_version` 并提供旧版本迁移测试。
- 完整版迁移前必须先创建整库快照，再运行公开版迁移逻辑。
- 私人角色资料与通用故事长期记忆保持不同数据域，避免公开导出意外包含私人数据。

### 2.3 图像后端

- 故事、存档、任务和导出模块不得依赖某一种具体图像模型。
- 当前公共 SDXL/ComfyUI 实现视为一个图像后端。
- 后续以统一接口接入 Qwen-Image、SDXL 增强工作流、LoRA、IP-Adapter 和 ControlNet。
- 通用任务层只接收任务状态、输出文件、耗时和错误，不直接理解工作流节点。

### 2.4 配置与私有覆盖层

- 通用默认配置进入 `.env.example`。
- 密钥、NSFW 提示词、私人角色、参考图片、本地数据库、生成图片和运行日志只存本地。
- 私有覆盖层使用 `.local/` 或环境变量加载，不修改通用模块源码。
- 公开仓库不得包含私有覆盖层的真实内容，只保留脱敏示例和接口说明。

## 3. 后续迁移方式

公开版后端完成后，按以下顺序迁移到完整运行环境：

1. 备份完整运行版的数据库、配置、角色资料和提示词。
2. 使用公开版模块替换旧版集中式网关核心。
3. 接入 Qwen-Image 和 SDXL 增强图像后端适配器。
4. 通过本地覆盖层加载私人角色与成人向提示词。
5. 运行数据库迁移、单元测试和接口回归测试。
6. 使用固定故事样例验证文本、记忆、图像、任务和导出完整链路。
7. 验证通过后再将公开版作为完整运行版的长期公共核心。

## 4. 阶段验收条件

在开始合并完整运行版前，公开版至少应满足：

- 后端通用功能和数据库结构稳定；
- 所有通用接口有自动化测试；
- 数据备份、恢复和迁移经过验证；
- 图像后端与任务管理完成解耦；
- Windows 部署与诊断脚本可重复运行；
- 真机 LLM 与 ComfyUI 端到端测试通过；
- 私有数据边界和 Git 忽略规则经过检查；
- 前端之外的毕业设计系统功能基本完成。

## 5. 禁止事项

- 不在公开版和完整运行版中同时手工实现同一功能。
- 不直接用公开版覆盖完整运行版目录。
- 不把完整运行版的 `.env`、数据库、日志、图片或角色资料复制到公开仓库。
- 不让通用业务模块直接读取私人角色文件或成人向提示词文件。
- 不在没有备份和回归测试的情况下执行数据库迁移。
