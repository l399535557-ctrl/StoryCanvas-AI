# StoryCanvas AI 当前完成情况与后续建设方向

更新日期：2026-10-03

## 一、项目定位

StoryCanvas AI 的毕业设计定位为：**面向交互式故事创作的本地多模态生成系统设计与实现**。

后续建设以“系统完整、流程闭环、可部署、可演示、可验证”为第一目标。论文中的深入研究
内容保留适当篇幅，主要用于说明方案选择和验证系统有效性，不把大量时间投入到训练新模型、
设计复杂检索算法或追求论文级理论创新。

毕业设计最终应呈现为一个完整软件工程，而不是若干模型接口的简单组合：用户能够创建故事、
持续对话、管理存档与记忆、生成和查看插图、恢复历史、导出成果；管理员能够配置模型、检查
服务、查看任务状态并诊断错误；项目具备测试、日志、部署和文档。

## 二、当前总体进度

目前已经完成系统的核心后端闭环：

```text
客户端输入
  -> FastAPI 网关鉴权与指令解析
  -> 按存档检索相关长期记忆
  -> 大语言模型续写故事
  -> 本地提取并保存新记忆
  -> 结构化视觉规划
  -> ComfyUI 本地图像生成
  -> WebP 图片与故事文本组合返回
```

当前阶段可定义为：**核心后端与主要生成链路已经完成，正在进入系统功能完善阶段**。

## 三、已经完成的功能

### 3.1 基础工程与接口层

- 使用 Python、FastAPI 和 Uvicorn 搭建异步 Web 服务。
- 实现 OpenAI Chat Completions 兼容接口，可接入 Chatbox、SillyTavern 等客户端。
- 实现 `/v1/models`、`/v1/chat/completions`、`/health` 和图片访问接口。
- 使用 Pydantic 校验请求数据，使用 `.env` 管理运行配置。
- 实现独立 Bearer Token 鉴权，避免直接暴露上游模型密钥。
- 实现标准 JSON 响应与分块 SSE 流式响应。
- 将配置、上游模型、状态、命令、提示词、图像工作流和记忆服务拆分为独立模块。

### 3.2 故事生成

- 接入 OpenAI-compatible 大语言模型服务。
- 支持系统提示词、故事设定文件和多轮消息输入。
- 对客户端消息进行清理和标准化，隔离具体模型服务商。
- 支持普通对话、强制插图和自动插图三种生成模式。
- 支持中文、英文以及移动端兼容的井号控制指令。

### 3.3 结构化视觉规划

- 将故事续写和图像提示词规划拆分为两个职责明确的阶段。
- 使用 JSON 表达人物、外观、服装、动作、镜头、场景、光照和风格等视觉字段。
- 支持从普通文本或 Markdown 代码块中提取 JSON。
- 实现标签清理、去重、分区组合和确定性回退，避免规划结果格式错误导致整轮失败。
- 使用单帧场景约束，减少同一图片中出现前后动作冲突的问题。

### 3.4 本地图像生成

- 通过 HTTP API 调用本地 ComfyUI 的队列、历史和图片接口。
- 动态构建 SDXL Core 节点工作流，无需在仓库中保存固定工作流文件。
- 支持分辨率、步数、CFG、采样器和调度器配置。
- 使用批量大小 1、生成锁和 Tiled VAE 适配约 8 GB 显存设备。
- 将输出转换为 WebP，并使用随机文件名提供访问。
- 支持可选 FaceDetailer 人脸细化，同时保持默认工作流依赖较少。
- 对 ComfyUI 超时、队列失败和无输出等情况进行错误映射。

### 3.5 分存档长期记忆与 RAG

- 使用 SQLite 建立 `story_saves`、`story_turns`、`memories` 和 FTS5 索引。
- 使用 `save_id` 隔离不同故事，防止跨存档记忆混入。
- 记忆包含类型、正文、标签、实体、重要度、故事时间和访问统计。
- 使用内容指纹去重，避免相同事实重复写入。
- 综合 FTS5、英文词项、中文双字词、重要度和时间因素进行本地混合检索。
- 使用 Top-K 和字符预算限制注入内容，避免长期故事撑满模型上下文。
- 在本地提取持久事件，不为记忆抽取额外发送一次外部模型请求。
- 支持请求字段、请求头和聊天命令选择存档。
- 实现存档列表、记忆列表和手动新增记忆的管理 API。

### 3.6 状态、安全和隐私

- 持久化自动插图开关和当前存档状态。
- 默认只监听本机地址，文档提供 Tailscale 私网访问方案。
- 图片路由限制文件类型并清理路径，降低目录穿越风险。
- 密钥、数据库、模型权重、生成图片和私人角色资料均排除在公开仓库之外。
- 公开版保留通用安全策略，不包含本地私人故事和成人向提示词配置。

### 3.7 测试、部署和文档

- 已有命令解析、内容策略、提示词编译、工作流、接口和记忆/RAG 单元测试。
- 当前自动化测试共 25 项，最近一次执行全部通过。
- 使用 Ruff 进行静态检查，并配置 GitHub Actions 持续集成。
- 提供 Windows 安装、启动、ComfyUI 冒烟测试和环境诊断脚本。
- 已建立 README、架构、API、安全、部署、项目介绍和变更日志文档。
- 大幅修改通过 `CHANGELOG.md` 留存目标、内容和公开同步边界。

## 六、后续设计方向与实施优先级

### 第一阶段：完成可操作的应用界面

优先开发独立 Web 前端，使系统不再依赖第三方聊天客户端完成主要操作。前端至少包含：

1. 故事对话与流式回复。
2. 新建、切换、重命名和删除存档。
3. 当前故事的记忆查看、增加、修改和删除。
4. 图片生成状态、结果预览和失败重试。
5. 模型连接、ComfyUI 状态和基础参数设置。

### 第二阶段：补齐数据与任务闭环

1. 完善存档、对话、图片和记忆之间的数据关系。
2. 增加对话历史分页和故事章节组织。
3. 增加图片任务状态、取消、重试和重新生成。
4. 增加记忆修订、失效和冲突处理机制。
5. 增加故事与图片的统一导出。

### 第三阶段：提高工程可靠性

1. 增加统一结构化日志、请求 ID 和错误码。
2. 补充数据库迁移、备份与恢复方案。
3. 完成 LLM、ComfyUI 和前端联合端到端测试。
4. 验证断网、模型不可用、显存不足和服务重启等异常场景。
5. 完善一键安装、启动、诊断和用户操作手册。

### 第四阶段：完成毕业设计验证材料

研究内容控制在支撑论文论证所需的范围，不扩展为独立算法研究。建议只保留两组容易
复现、能体现工程价值的实验：

1. **长期记忆效果对比**：完整历史、无记忆、RAG 检索三种方式的上下文长度、响应
   时间和关键事实保持率。
2. **视觉规划效果对比**：直接使用故事文本与结构化视觉规划在图文一致性、人物属性、
   动作正确率和生成成功率上的差异。

同时整理系统架构图、数据库设计、接口说明、关键流程时序图、测试结果、运行截图和演示
视频。这些材料共同证明设计合理性与工程工作量。

## 七、毕业设计完成标准

项目达到以下条件时，可以认为形成了完整的毕业设计成果：

- 普通用户能够通过独立界面完成从创建故事到导出作品的完整流程。
- 文本生成、长期记忆、插图生成、历史恢复和错误处理能够协同工作。
- 关键数据有明确的数据表、接口和备份方式。
- 常见异常具有可理解的提示，并可重试或恢复。
- 项目可以在目标 Windows 设备上按照文档独立部署。
- 单元测试、接口测试和核心端到端测试均有记录。
- 论文能够围绕需求分析、总体设计、数据库设计、模块实现、系统测试和少量对比实验展开。

## 八、结论

StoryCanvas AI 已经完成最关键的后端技术链路，现阶段不需要继续盲目增加模型或复杂算法。
后续应围绕前端、数据管理、任务管理、错误恢复、导出、部署和测试逐项补齐，使其成为一套
可独立使用、可稳定演示、可清晰答辩的完整多模态故事创作系统。
